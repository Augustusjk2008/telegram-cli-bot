# Agent Guide

> **Sync rule:** `AGENTS.md` and `CLAUDE.md` must stay identical. When you edit one, apply the same change to the other in the same task.

Orbit Safe Claw is a Windows-first Python web console for local Codex (`codex exec` or `codex app-server`), Claude, Antigravity (`agy`), and DeepSeek Harness (`dsh`). Optional Telegram and personal Weixin iLink gateways share the Web sessions. The following rules apply to the entire repository.

## Sessions and Security Boundaries

- Do not proactively shut down, restart, or kill the current agent itself, or cause the current agent to exit by stopping services, restarting services, or similar means.
- If you need to restart `python -m bot`, the web service, or other host processes, have the user do it first, or obtain explicit instructions.
- The agent must not start any development or preview services, including `npm run dev`, Vite dev server, `vite preview`, temporary HTTP servers, etc., nor keep listening ports in the background; when development services are needed, the user should start them themselves.
- Preserve the user's existing changes; do not use destructive Git commands to overwrite work that does not belong to the current task.

## Common Commands

```bash
# Install / Start
bash install.sh
bash start.sh
python -m bot

# Backend
python -m pytest tests -q

# Frontend
cd front && npm run test:gate
cd front && npm run build
cd front && npm run lint
```

Do not assume that `venv/` in the repository is usable on all machines. Prefer the currently activated Python environment unless the local venv has been verified.

Use Node.js 22.13+ for the locked frontend dependencies and installer checks.

- Source launchers `start.bat`, `start.ps1` and `start.sh` use the existing `front/dist` assets; after frontend changes, run `cd front && npm run build` explicitly before restarting the host. Admin Center can request a backend restart, while an AI agent must not trigger that restart proactively.

### Local Browser Tests

Use the installed Google Chrome with the project's Playwright; Windows selects Chrome automatically. From `front/`, reuse a user-started application:

```powershell
$env:PLAYWRIGHT_BASE_URL = "http://127.0.0.1:8765"
npm run e2e:smoke
```

The smoke test covers login-page input, tab switching, desktop/mobile layout and screenshots. Run feature tests with `npm run e2e -- src/test/<feature>.spec.ts`, keeping `PLAYWRIGHT_BASE_URL` set.

## Repository Boundaries

- `bot/` contains the backend, Web API, bot manager, plugin implementations and optional Telegram/Weixin gateways; `front/` is the React/Vite frontend; `tests/` is the backend pytest.
- Do not commit or force-add `.env`, the real `managed_bots.json`, `docs/` runtime materials and release notes, or data under the user directory `.tcb/`.
- `managed_bots.example.json` is for public examples only. Web Bot profiles share one optional Telegram gateway; there is no per-profile Telegram application lifecycle. Gateway configuration uses `TELEGRAM_ENABLED`, `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ALLOWED_USER_IDS` and `TELEGRAM_BROADCAST_COMPLETIONS`.
- Brand/logo consistently uses `front/public/assets/app-logo*.svg`; login, favicon, mobile shell, and workbench header remain consistent.
- The in-app usage tutorial lives in `front/src/tutorial/`. Its screenshots under `front/public/assets/tutorial/` and `front/src/tutorial/shots.generated.json` are generated by `npm run tutorial:shots` from mock data; regenerate them when the UI changes instead of editing them by hand.
- Configuration is loaded from environment variables in `bot/config.py`; `.env` uses `python-dotenv`.
- Resolve runtime locations through `bot/runtime_paths.py`: the storage locator takes precedence after migration, while `TCB_DATA_DIR` only overrides the application data root before migration. Plugins and chat history follow the storage root; do not assume every runtime file is under `TCB_DATA_DIR`.
- Fixed public forwarding must retain the `/node/<node ID>/` path prefix and support WebSocket; for configuration and minimal `frps`/`frpc` examples, see `README.md`.

## Core Invariants

- Web sessions are isolated by `(bot_id, shared_user_id, agent_id)`; Web user IDs are normalized via `chat_session_user_id()`.
- When user text starts with `//`, rewrite it to `/...`; Codex CLI uses JSON output.
- CLI types are `codex`, `codex_server`, `claude`, `antigravity` and `deepseek`. `codex_server` uses `codex app-server --stdio` under `execution_mode=cli`, with its own parameter namespace. DeepSeek supports local CLI execution and cluster MCP; remote workspaces and Git commit-message generation remain unsupported.
- CLI keeps SSE `meta/status/trace/done`, with incremental body preview placed in `status.preview_text`.
- The top level of CLI SSE `meta/status/trace/done` must retain `turn_id` and `assistant_message_id` to stably bind the current turn.
- CLI execution details display tool calls, results and context usage in the chat transcript.
- Trace transport: a Web client may ask for compact trace events (`trace_payload: "compact"` on the chat stream, `payload=compact` on the trace endpoint). Summaries and payloads over the preview limits in `bot/web/trace_compaction.py` are then capped and marked `content_truncated` with their original sizes, and the full event is read from `/history/{message_id}/trace/event`. Persistence, other channels and requests without the option keep full events.
- The notifications WebSocket announces `chat_sync` in `hello.features` and pushes content-free `chat_sync` hints (Bot alias, agent, reason) when a shared session changes (`bot/web/chat_sync_events.py`); hints reach only accounts that can operate the Bot. Web chats sync on a hint and keep polling at a slower fallback, so correctness never depends on a hint.
- Local cluster orchestration supports all five CLI types. Bot-level `max_parallel_agents` is normalized to 1–20. All backends share model and reasoning tiers; per-task overrides use the queued configuration snapshot without changing the main Bot configuration. Antigravity uses workspace MCP configuration, DeepSeek uses a per-turn Harness patch. Remote Antigravity cluster orchestration is rejected before launch. The main agent can call `cancel_agent_task(task_id)` to stop one queued or running child task without stopping other tasks in the same run.
- Cluster `run_id` is stable for the main conversation and team revision. Every MCP call passes it explicitly; after `configure_team` returns `changed=true`, subsequent calls use its returned ID. Ordinary turns and host restarts do not rotate it; in-memory tasks do not survive host restarts.
- Endless mode groups automatic `Continue` attempts by `endless_group_id`. Retryable incomplete or error results wait for `ENDLESS_CONTINUE_DELAY_SECONDS` (default 120 seconds), persist `error` and `continue` events in ChatStore, and reuse one durable turn for the whole run. Legacy grouped turns are consolidated in the database; history loading returns the turn directly. Session state exposes whether endless mode is active and its attempt count; stopping or cancelling the run must end the continuation loop.
- Telegram and Web share `(bot_id, shared_user_id, agent_id)` sessions. Telegram bindings also identify the conversation; delivery retries and broadcast expansion read persisted replies without replaying agent tasks. Keep the Telegram whitelist separate from Web user IDs and never expose the Bot token.
- Personal Weixin iLink and Web/Telegram share `(bot_id, shared_user_id, agent_id)` sessions. Weixin uses QR onboarding, HTTP long polling, a separate `WEIXIN_ALLOWED_USER_IDS` private-message allowlist and a SQLite state store for cursors, context tokens, bindings and delivery recovery. Keep the Weixin token out of API responses, frontend state, logs and SQLite; ordinary groups and non-text media are outside the current scope.
- The theme library is the shared set of packaged presets and is read-only for every account: creating, importing, updating or deleting themes and uploading theme assets return `theme_readonly`. Each signed-in account keeps its own selected theme, falling back to the default theme; the login page reads `/api/public/ui/themes` and stores its preview selection only in the browser. Guests cannot change the selection; selection changes check the library revision to avoid overwriting concurrent changes. List and selection responses carry `themesDigest`; a client that sends the digest it holds as `themes_digest` gets the account state without the theme list.
- GitHub connections belong to the signed-in Web account (`bot/web/github_service.py`); tokens are encrypted under the app data `github/` directory and never returned to clients. Local fetch/pull/merge/push/publish pass the requester's token to Git only through environment-scoped `http.https://github.com/.extraheader`, never argv; SSH remote workspaces keep using the remote host's credentials and never receive the token.
- Scheduled tasks (`bot/scheduler/`) are admin-only (`admin_ops`) and target a Bot's `main` agent in the shared session: each run calls `create_conversation` and then `stream_chat` with `source_channel="schedule"`, so it switches that Bot's active conversation. Each fire is claimed once per `(schedule_id, planned_at)`, a schedule never overlaps itself, busy Bots wait or skip according to the schedule, and fires missed beyond the grace window are recorded as `missed`, never replayed. No run starts while the host drains for an update, restarts or migrates storage; unfinished runs become `interrupted` on restart. `allow_unsafe_cli` requires `run_unsafe_cli` from the account that last changed the prompt, Bot or flag, and is re-checked before every run.
- Cost statistics (`bot/cost_stats/`, admin Cost page) are per provider (`codex`, `claude`) and disabled by default; while disabled, recording and the Codex previous-total lookup do no disk I/O and create no database. `with_estimated_cost` in `_stream_cli_chat` records one row per CLI invocation, keyed by an invocation ID so repeated calls overwrite it, best-effort and never failing the turn. Codex exec turns are priced from their own tokens (`CliTurnCost` sums the increases of the rollout's `token_count` running counter inside the turn, at the turn's model) and carry `estimated_cost.basis = "turn"`, so nothing is subtracted from them; only when the rollout is unavailable does the legacy `turn.completed` running total apply, where the store keeps the increase over the previous running total (equal records 0, lower is a reset) minus per-turn records in between. Claude and app-server amounts are stored as reported. Cluster child tasks are stored under their own agent ID, which the Cost page does not show (their cost is summed into the Bot), with the `cost_user` snapshotted from the run when queued; the main agent's wake-up turns use the woken tasks' `cost_user`, as cost-only attribution that never changes the chat author. Queries aggregate once in SQL over `(provider, day)` and return a dictionary-encoded cube the frontend pivots locally.
- Editor language features (`bot/language_server/`, disabled unless `TCB_LSP_ENABLED`) cover clangd, pyright and the TypeScript server. Definition and implementation use `/workspace/code-navigation/resolve`; hover, references, document symbols, semantic tokens, completion and diagnostics use `/workspace/code-intelligence/query`, which shares navigation's document sync, cancellation by request ID and runtime recovery. Positions are 1-based lines with code-point columns. A disabled, missing or incapable server answers `available: false` or `supported: false` instead of an error, and the editor then falls back to grammar highlighting plus naming-convention colours, with semantic tokens taking precedence when present. The clangd status item carries `configuration` (`compile_commands`, `project_config` or `fallback`); `--query-driver` stays rejected.
- Web terminal sessions are isolated by `(user_id, owner_id)`; each new tab must use an independent `owner_id`, and closing a tab must terminate the corresponding shell; the legacy client's `rebuild` endpoint is retained as a compatibility alias for creating sessions.
- Updates use installation-scoped `UpdateStore` state and one durable preparation job. Downloading only prepares a job; applying requires its ID, current revision and an idle host. Exit `75` is an ordinary restart; `76` hands a confirmed job to the official launcher's frozen, standard-library executor. Preserve backups until health verification and retain recovery materials on uncertainty. Never apply updates or restart the current host as an automated validation step.
- Direct and supervised hosts share installation locks in the external control directory. Storage migration must preserve this lock identity; the host reports its current update-state location through an authenticated process handoff. Keep new work paused until the executor confirms the new or restored host.
- Update manifests own program files only. Preserve runtime paths, user data and local modifications. Program rollback cannot imply data rollback. Verify new migration compatibility before application. `scripts/update_package.py` checks payload identity/integrity; the legal-file verifier checks required notices only.
- Announcements belong to each deployment. Admin Center publishes them to that host’s users. Store content and read state in the active TCB app data root. Release packages and program updates must keep host announcements private.

When modifying CLI execution, cluster orchestration, remote workspace/terminal/Git bridge, plugins, or the installation/release chain, use the repository-level `orbit-maintenance` skill, and read only the references corresponding to the affected subsystems. Current source, pinned dependencies and tests determine implementation status; keep these instructions, skill references and both root READMEs consistent when their documented contracts change.

## Verification

- Use minimal sufficient testing: add tests for stable contracts, high-risk logic, important boundaries, security/data integrity issues and real bug regressions. Ordinary copy, styles and mechanical edits do not need new tests; documentation changes need source, command and link checks.
- Before completion, run tests, builds, or smoke checks matching the changes, and report the actual results; if unable to run them, explain why.
- The backend uses `pytest`, `pytest-asyncio`, and `unittest.mock`; no backend linter/type checker is currently configured.
- The frontend uses Vitest, Testing Library, and Playwright; when layout is involved, run browser-level checks.
- Avoid duplicating assertions of the same fact across the component, page, and shell layers; keep only the most appropriate layer.
